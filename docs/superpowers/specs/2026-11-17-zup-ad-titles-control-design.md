# Сверка должности и отдела: ЗУП ↔ Active Directory (контрольный список)

Дата: 2026-11-17. Статус: утверждено (решения приняты в ходе авто-сессии, см. «Решения»).

## Зачем

В AD у учётных записей сотрудников атрибуты `title` (должность) и `department` (отдел)
поддерживаются вручную и расходятся с кадровыми данными ЗУП. Нужен контроль: брать эталон
из ЗУП, сравнивать с AD и показывать расхождения в контрольных списках реестра.

## Решение: расширить список «Расхождения данных» (kind=quality)

Список `quality` уже сверяет данные систем с кадрами (профили Битрикс24, руководители
Битрикс24, employeeNumber в AD). Добавляем две области: `AD: должность` и `AD: отдел`.
Новый вид списка не создаётся — всё существующее (гашение с журналом, права, MCP,
дашборд) работает без изменений.

Отвергнуто:
- **Отдельный список** (`titles`) — тот же смысл, но дублирует plumbing: CONTROLS,
  SUPPRESSIBLE, заголовки на фронте, права профилей. Не даёт преимуществ.
- **Desk Script Report** — нет гашения/журнала, выпадает из «Контроля».

## Поведение

Строка расхождения появляется, когда одновременно:
- у сотрудника есть привязанная учётка AD (`tabAD Account.person`), учётка включена,
  не помечена «Нет в AD» (`missing_in_source = 0`);
- сотрудник работает (`tabPerson.status = 'Работает'`).

Сравнение (для каждого из двух полей отдельно):
- **Эталон (expected)**: должность/отдел основного активного трудоустройства
  (`ОсновноеМестоРаботы` среди активных; если основного нет — единственное активное;
  названия — `title` из `HR Position` / `HR Department`). Активное трудоустройство —
  тот же набор статусов, что в `access_registry.sync.persons.ACTIVE_EMPLOYMENT_STATUSES`.
- **Факт (current)**: `title` / `department` учётки AD. Пустое значение AD — тоже
  расхождение (current показываем «—»).
- **Сравнение**: нормализованное точное совпадение — `lower()`, `ё→е`, схлопывание
  пробелов по краям и подряд (тот же стиль, что `engine.py` для ключевых слов должностей).
  Не совпало — строка в список.
- Нет активного трудоустройства — эталона нет, строку не пишем.

Колонки — как у остальных строк quality: `Кто или что` (person), `Где расхождение`
(area: «AD: должность» / «AD: отдел»), `Сейчас` (AD), `Должно быть (по кадрам)` (ЗУП).
В строке заполняются `person`, `ref` = имя учётки AD, `ref_doctype` = «AD Account»,
`system` = «AD» — для журнала, гашения и фильтра по системам (`aa.filter_rows`).

Ключ гашения quality — `(area, person, full_name)` — уже различает должность и отдел,
новый SUPPRESSIBLE не нужен.

Вычисление — на лету при открытии списка (как остальные контроли), хранение не добавляем.

## Что трогаем

- `access_registry/registry/api.py` — `_control_quality()`: добавить выборку
  AD-учёток с должностями/отделами ЗУП и две строки расхождения на учётку.
- Тесты: `access_registry/tests/test_registry_control.py` — кейсы: совпадение,
  расхождение должности, расхождение отдела, пустой атрибут в AD, несовпадение
  регистра/пробелов/ё — не расхождение, уволенный/отключённая учётка — не в списке,
  нет активного трудоустройства — не в списке.

Фронтенд, MCP, права, подавление, дашборд — без изменений.

## Решения (приняты за пользователя, авто-режим)

1. Расширяем `quality`, отдельный список не создаём.
2. Только работающие сотрудники с активной учёткой AD.
3. Пустой `title`/`department` в AD — расхождение (AD «должен отображать» кадры).
4. Нормализация при сравнении: регистр, ё/е, пробелы; семантическое соответствие
   («Бухгалтерия» vs «Финансовая служба») вне рамок — гасится вручную, если ОК.
5. При совместительстве без основного места эталон — единственное активное
   трудоустройство; несколько активных без основного — первое по дате приёма.
