# Отчёты по технике «Пересорт» и «Ошибки учёта» — дизайн

Дата: 2026-11-03. Статус: согласовано в обсуждении, ожидает утверждения.

## Зачем

По технике (Snipe-IT) есть общие отчёты («Техника», «Движения техники», «Техника другой
организации») и доска с количеством отклонений, но нет отчётов, которые одним списком
отвечают на два вопроса учёта: «что числится не там» и «какие карточки ведутся криво».

Цель: два Script Report'а — «Пересорт» и «Ошибки учёта».

## Решения (приняты в обсуждении)

- Разбиение: пересорт — техника не за теми людьми/организациями; ошибки учёта — кривые
  карточки (пустые поля, дубли, противоречия статусов, просрочки).
- Отчёт «Техника другой организации» поглощается «Пересортом» (удаляется, его строки
  становятся одним из видов проблем).

## Подход

Один разумный способ: Script Report по образцу существующих (`it_assets/report/*` —
`.py` + `.js` + `.json`, роли доступа как у «IT Assets», ссылки в workspace «Техника»).
Альтернативы (раздел в приложении `/registry`, новые DocType) не подходят: данные уже в
базе, а доска `/registry` уже даёт сводку — не хватает именно детальных списков.

## Отчёт «Пересорт» (`IT Assets Misallocation`)

Одна строка на (техника, проблема), колонка «Проблема» + фильтр по виду проблемы:

1. «Куплена на другую организацию» — как в поглощаемом отчёте (`orgs.other_org_assets`);
2. «Числится за неработающим» — выдана сотруднику со статусом ≠ «Работает»;
3. «Выдана не сотруднику» — в Snipe-IT выдача на пользователя, не привязанного к Person;
4. «Выдана сотруднику, но числится иначе» — последняя передача (checkout) — сотруднику,
   а сейчас техника в месте / на другой технике / у другого сотрудника (по `IT Asset Event`).

Колонки: техника, инв. номер, категория, проблема, сотрудник, статус сотрудника,
«куплена на» / «кому в Snipe-IT», выдана когда, ссылки на карточки. Фильтры: сервер,
категория, сотрудник, вид проблемы.

## Отчёт «Ошибки учёта» (`IT Assets Data Issues`)

Одна строка на (техника, ошибка), колонка «Ошибка» + фильтр по виду:

1. нет инвентарного номера; 2. нет серийного номера; 3. нет даты покупки;
4. нет стоимости; 5. дубль инв. номера (у активных); 6. дубль серийника (у активных);
7. списана (archived), но числится выданной; 8. неисправна (undeployable), но числится
за сотрудником; 9. просрочен возврат; 10. просрочен аудит.

Колонки: техника, инв. номер, категория, ошибка, сотрудник, статус, место, ссылки.
Фильтры: сервер, категория, вид ошибки.

## Прочее

- Workspace «Техника»: удалить ссылку на «IT Assets Other Organization», добавить две
  новые (проверяет `test_workspace`).
- Сам отчёт «IT Assets Other Organization» удаляется (папка report'а). Общий хелпер
  `it_assets/orgs.py` остаётся — им пользуется и доска.
- Доску «Оборудование» не трогаем: определения совпадают (Person.status,
  `other_org_assets`), но рефакторинг общего кода доски не делаем — моё решение, чтобы
  не раздувать изменение.

## Решения, принятые мной (можно оспорить)

- Плоский список «одна строка = одна проблема», а не группировка по технике: проще
  фильтровать и экспортировать; у одной единицы может быть несколько строк.
- Проблема 4 пересорта — по последнему событию выдачи; если истории нет, строки нет.
- Просрочка возврата/аудита живёт в «Ошибках учёта», а не в «Пересорте» (уже
  обсуждено, здесь для полноты).

## Не делаем (anti-goals)

- Не меняем доску «Оборудование» и её счётчики.
- Не добавляем эти отчёты в приложение `/registry` (можно позже отдельно).
- Не чиним данные автоматически — отчёты только показывают.

## Тесты

- `test_it_assets_reports`: оба отчёта на фикстурах — каждый вид проблемы ловится,
  чистая техника не попадает; дубли считаются только по активным; поглощённый отчёт
  удалён из workspace и modules (покрывается существующими `test_workspace`,
  `test_navigation`).
