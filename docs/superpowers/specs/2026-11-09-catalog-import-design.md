# Каталог прав из систем + импорт ролевой модели из Excel — дизайн

Дата: 2026-11-09. Статус: согласовано в обсуждении («давай»), реализуется.

## Зачем

Владелец ролевой модели должен был вручную создавать карточки прав (Entitlement),
хотя все права уже есть в системах-источниках (группы AD, профили 1С, группы Б24) и
зеркалируются в реестр. Связка «роль → право → системный артефакт» существует, но
массовые пути её заполнения спрятаны в отчёте «Доступы вне каталога», а импорта из
Excel в разделе нет вообще.

## Решения (приняты в обсуждении)

- Каталог остаётся обязательным слоем (название, риск, владелец, SoD, пересмотр);
  расширяем способы его наполнения, а не убираем его.
- Два новых пути наполнения: (1) «Заполнить каталог из систем» прямо в разделе
  «Роли доступа» приложения; (2) xlsx-импорт прав и ролей по образцу импорта
  бизнес-процессов.

## Что делаем

### 1. Заполнение каталога из систем (приложение /registry)

- Новый модуль `access_registry/access_roles/catalog.py`:
  - `catalog_candidates(min_holders, system)` — GET; права системы, есть у сотрудников,
    но ещё не в каталоге (поверх `engine.actual_entitlements()` + `describe_key()`):
    ключ, название, система, у скольких есть, поля привязки.
  - `catalog_add(keys)` — POST; обёртка над `engine.ensure_entitlement` (создаёт
    карточки с привязкой, эвристика риска). Права: раздел «Роли доступа» на уровне
    «Работа» через `app_access.require_section` (пользователи с профилем без desk-роли
    тоже смогут; существующий desk-экшн `add_to_catalog` не трогаем).
- `registry.js`, раздел «Роли доступа»: кнопка «Заполнить каталог из систем» — модалка
  с таблицей кандидатов, галочками, «Добавить отмеченные» и «Добавить все».
- Раздел «Права доступа»: в пустом каталоге подсказка с этой же кнопкой.

### 2. Импорт ролевой модели из Excel

- По образцу бизнес-процессов: DocType «Импорт ролевой модели» (Role Model Import):
  файл, статус (Новый/Проверен/Загружен/Есть ошибки), сводка, ошибки по строкам,
  кнопки «Проверить» и «Загрузить».
- `access_registry/access_roles/xlsx_io.py`: один workbook, два листа.
  - «Права»: Название*, Система* (1С/Active Directory/Битрикс24/Другое), Риск,
    Привилегированное, Владелец, Что даёт, AD-группа, Профиль 1С, Группа Б24.
    Upsert по паре (Название, Система); привязки ищутся по имени в зеркалах
    (не найдена — ошибка строки).
  - «Роли»: Роль*, Вид, Описание, Статус, Права (названия через «;»),
    Обязательные (подмножество; по умолчанию «По необходимости»).
    Upsert по имени роли; состав прав заменяется списком из файла.
  - Всё-или-ничего: любая ошибка строки — ничего не сохраняется, все ошибки
    перечислены (как в импорте процессов).
- Скачивание шаблона (такой же workbook с заголовками и примером).
- Ссылка в workspace «Ролевая модель» (инвариант: новые справочники видны в workspace;
  проверяет `test_workspace`).

## Подходы

- Импорт — desk-DocType по образцу Process Import (выбрано): тот же паттерн «файл →
  проверить → загрузить», переиспользуемые кнопки и права; альтернатива (загрузка
  base64 прямо из приложения) дублировала бы механику и дала меньше контроля.
- Права на новые endpoint'ы — через раздел приложения (`require_section`), а не desk-роль:
  владелец ролевой модели работает из профиля без desk-лицензии.

## Решения, принятые мной (можно оспорить)

- Кандидаты в каталог — только права, есть минимум у 2 сотрудников (минимум
  настраивается; по умолчанию 1, как в отчёте).
- Импорт ролей не трогает правила назначения (должность/подразделение): файл задаёт
  только состав прав. Правила — отдельная тема.
- Владелец права в импорте — по имени сотрудника (Person), не по e-mail.
- «Добавить все» добавляет все строки текущей выборки, а не только первую страницу.

## Не делаем (anti-goals)

- Не меняем модель данных Entitlement/Access Role, отчёт «Доступы вне каталога»,
  desk-экшн `add_to_catalog`.
- Не импортируем правила ролей, SoD, исключения.
- Не делаем экспорт ролевой модели в Excel (импорт + шаблон достаточно для старта).

## Тесты

- `test_roles_catalog.py`: кандидаты (состав, фильтр по системе, права — 403 без
  «Роли → Работа», чтение — без «Работа»); добавление (создание, дедуп, привязка);
  xlsx (создание/обновление прав, создание роли со связкой, ошибки строк — всё или
  ничего, неизвестная привязка, шаблон скачивается).
