# Access Registry — инструкции для агента

Реестр «кто есть кто и у кого какой доступ» на Frappe Framework v15. Собирает слоями:
кадры ЗУП → Active Directory → пользователи 1С → Битрикс24 → общие папки Synology →
ролевая модель и бизнес-процессы. Плюс техника (Snipe-IT), техподдержка и подбор
(смарт-процессы Битрикс24).

Полная документация — в `README.md` (~1200 строк, эксплуатация) и `docs/`:
- `docs/architecture.md` — слои, DocType, правила добавления нового источника (читать первым)
- `docs/roles-and-processes.md` — ролевая модель, почему должность ≠ роль
- `docs/deployment.md`, `docs/docker.md`, `docs/dev-setup-wsl.md`, `docs/sso.md`

## Структура кода

- `access_registry/` — приложение Frappe; модули перечислены в `modules.txt`
- `access_registry/sync/engine.py` — ядро загрузки ЗУП (транзакция, предохранитель)
- `access_registry/access_roles/engine.py` — сверка «положено / есть», SoD, role mining
- `access_registry/registry/api.py` — API приложения `/registry` (большой файл; новые
  разделы выносить в отдельные модули)
- `access_registry/www/registry.js` — фронтенд приложения, чистый JS без сборки
- `onec/` — расширения 1С (BSL), `bitrix24/registry_export.php`, `synology/` — скрипты сборщиков
- `tools/generate_synthetic.py` — генератор синтетических данных и заглушки API 1С

## Инварианты, которые нельзя нарушать

1. Источники (1С, AD, Synology, Snipe-IT) — **только чтение**. В Битрикс24 пишем только
   отчество, дату рождения и UUID сотрудника, и только если включено в настройках портала.
2. Каждый метод API сам проверяет права (`permissions.py`, `app_access.py`) — скрытие
   кнопки на фронте защитой не считается. Изменяющие действия — только POST.
3. Персональные данные (ФИО, даты рождения) не попадают в Sync Log и сообщения
   (`PERSONAL_KEYS` в `sync/engine.py`); секреты, токены и вебхуки вычищаются
   (`redact.py`). Даты рождения видят только администраторы и аудиторы.
4. Записи источников именуются `<код источника>:<идентификатор>`, хранят хеш данных,
   сохраняются только при реальных изменениях; пропавшие — помечаются, не удаляются.
5. Каждый запуск загрузки пишется в Sync Log; вся загрузка — в одной транзакции
   (savepoint), срабатывание предохранителя откатывает всё, кроме Sync Log.
6. План изменений AD — «четыре глаза»: решение принимает не автор, одобренный план
   неизменяем, реестр в AD не пишет (скрипт запускает администратор).

## Стиль

- Python 3.10+, Ruff: длина строки 110, **табы**, двойные кавычки (`pyproject.toml`)
- Код и комментарии — на английском; тексты интерфейса и сообщения пользователю — на русском
- Новые scheduled-задачи: имена методов должны различаться в последних двух частях
  (см. комментарий в `hooks.py`, `test_scheduler_names`)
- Любой новый справочник в админке должен иметь ссылку в workspace (проверяет тест)
